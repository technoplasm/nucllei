# ツール・スキル・拡張の違い

この文書は、nucllei に出てくる 3 つの拡張の仕組み **ツール** / **スキル** / **拡張 (Function)** を
横に並べて比べたものです。「何が違うのか」「いつどれが動くのか」「やりたいことはどれで作るのか」を
1 枚で見るための文書で、それぞれの画面の操作は各章 (「ワークスペース > ツール」「同 > スキル」
「同 > 拡張」) にあります。

スキルがツールを連れてくる仕組み (遅延ロード) は、この文書ではなく「スキルの遅延ロード」にあります。

## 1 行でいうと

- **ツール** — モデルが会話の途中で呼び出せる Python の関数のまとまり。
- **スキル** — モデルに必要なときだけ読み込ませる Markdown の手順書。
- **拡張 (Function)** — リクエストや応答の流れに割り込んで処理を足すサーバー側の Python。

**呼ぶ主体が違います。** ツールを呼ぶのはモデル、スキルを起動するのはモデルまたは利用者、
拡張を走らせるのはシステムです。

## 対比表

|                                  | ツール                                                     | スキル                                                                              | 拡張 (Function)                                                                                                      |
| -------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 中身                             | Python の関数のまとまり                                    | Markdown の手順書                                                                   | Python のコード                                                                                                      |
| **誰が呼ぶか**                   | **モデル**                                                 | **モデル**、または利用者が `/スキル ID` で起動                                      | **システム** (種別ごとに自動。Action だけは人がボタンを押す)                                                         |
| **いつ動くか**                   | 会話の途中、モデルが必要と判断したとき                     | モデルが読み込んだとき / 利用者が `/` 付きで送ったとき                              | 決まったタイミング (下の「拡張はどこに割り込むか」)                                                                  |
| **誰が作れるか**                 | 管理者のみ                                                 | 管理者、または「スキル編集者」権限を持つ人 (**ツールを紐づけたスキルは管理者のみ**) | 管理者のみ                                                                                                           |
| **モデルから見えるか**           | 見える。関数ごとに名前と説明がモデルに提示される           | 一覧だけ見える (`ID: 説明` の 1 行ずつ)。本文は読み込むまで見えない                 | **見えない**。モデルは拡張の存在を知らない                                                                           |
| **どのモデルで効くか**           | 「ワークスペース > モデル」で割り当てたモデル              | 同左。加えてそのモデルの「能力」で「スキル」がオンであること                        | Filter / Action は同左。Attachment は「設定 > ファイル」で選んだ 1 つが全体に効く。Pipe は存在すればモデル一覧に出る |
| **公開範囲 (ACL)**               | ある (「公開」/「非公開」)                                 | ある                                                                                | **無い**。誰に効くかはモデルへの割り当てで決まる                                                                     |
| **モデルのコンテキストを食うか** | 食う。割り当てた**全ツール**の説明が毎回のリクエストに載る | ほとんど食わない。一覧の 1 行ずつだけ。本文と付属ツールは読み込んだときだけ載る     | 食わない (Filter が本文そのものを書き換える場合を除く)                                                               |
| 管理する画面                     | ワークスペース > 「ツール」                                | ワークスペース > 「スキル」                                                         | ワークスペース > 「拡張」                                                                                            |
| チャット画面で選べるか           | 選べない                                                   | `/` で起動できる                                                                    | 選べない                                                                                                             |

## 拡張はどこに割り込むか

拡張は 4 種別あり、種別はコード中のクラス名 (`Filter` / `Attachment` / `Action` / `Pipe`) で決まります。
それぞれ流れの別々の場所に入ります。

```
利用者が送信
   ↓
 Filter の inlet …… モデルへ送る手前。本文やパラメータを書き換える / 弾く
   ↓
 ツールの解決・添付本文の差し込み
   ↓
 モデル (Pipe を選んでいれば、モデルの代わりにこの拡張が応答を作る)
   ↓
 Filter の stream …… 応答が届く途中の断片ごと
   ↓
 応答の完了
   ↓
 Filter の outlet …… 出来上がった 1 ターン分に対して

  別の流れ:
 ファイルのアップロード → Attachment …… ファイルからテキストを取り出す
 応答の下のボタンを人が押す → Action …… 押されたときだけ動く
```

| 種別       | 割り込む場所                                                               | 用途の例                                                 |
| ---------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| Filter     | モデルへ送る前 (`inlet`) / 応答の途中 (`stream`) / ターン完了後 (`outlet`) | 匿名化などの前処理、パラメータの調整、ログ、応答の後処理 |
| Attachment | ファイルがアップロードされたとき                                           | ファイルからテキストを抽出して本文にする                 |
| Action     | 応答の下に出るボタンを人が押したとき                                       | 応答に対する後付けの操作                                 |
| Pipe       | モデルとして選ばれたとき                                                   | 独自のモデル・ルーティングを作る                         |

**Filter は「割り当てること自体が有効化」です。** 全モデルに一括で効かせるトグルはありません。
匿名化のように全体に効いてほしい Filter は、**すべてのモデルに割り当てる**必要があります。
新しくモデルを作ったときに付け忘れるのが、いちばんよくある事故です。

## やりたいことはどれで作るか

| やりたいこと                                                                   | 使うもの                                  |
| ------------------------------------------------------------------------------ | ----------------------------------------- |
| 計算する、検索する、外のシステムを叩く、ファイルを作る                         | **ツール**                                |
| 決まった手順・書式・言い回しでやらせる。特定の話題のときだけ追加の指示を与える | **スキル**                                |
| ある作業のときだけ、その作業に必要なツールを持たせる                           | **スキル**にツールを紐づける (管理者のみ) |
| すべてのリクエストに必ず挟む (匿名化、ログ、注意書きの付加)                    | **拡張** の Filter                        |
| アップロードされたファイルからテキストを取り出す                               | **拡張** の Attachment                    |
| 応答のあとに人がボタンで実行する操作                                           | **拡張** の Action                        |

## モデルは何を手がかりに選ぶのか

**説明文だけ**です。モデルはツールやスキルの中身を見ずに、名前と説明を読んで「これを使う」と判断します。
したがって次のようになります。

- **スキルの「説明」が空だと、モデルには公開されません。** 一覧にも載らないので、モデルは
  そのスキルが存在することすら知りません (利用者が `/スキル ID` で起動することはできます)。
  「ワークスペース > モデル」のスキル割り当ての欄では、説明が空のスキルに「(説明なし)」と
  黄色で注記が付きます。
- **ツールでモデルが読むのは、関数に書いた説明 (docstring) です。** 一覧画面の「説明」欄は
  管理画面に出る短い説明で、モデルには渡りません。モデルに伝えたいことは各関数の docstring に書きます。
- 説明が曖昧だと呼ばれません。「何ができるか」よりも**「どういうときに使うか」**を書くと選ばれやすくなります。

## つまずきやすいところ

- **モデルがツールを呼んでくれない** — そのモデルにツールが割り当てられているか、
  公開範囲が「非公開」のときに対象の利用者が含まれているか、関数に説明 (docstring) があるかを確認します。
- **モデルがスキルを使ってくれない** — 「説明」が空ではないか、モデルの「能力」で「スキル」が
  オンか、そのモデルにスキルが割り当てられているかを確認します。3 つとも満たさないと働きません。
- **拡張が動かない** — Filter / Action はモデルへの割り当てが必要です。割り当てていないモデルでは
  動きません。Attachment は「ワークスペース > 設定 > ファイル」で選ばれている 1 つだけが動きます。
- **ツールを増やしたら応答が雑になった** — 1 つのモデルに割り当てたツールの説明はすべて毎回
  モデルに提示されます。数が増えるほどコンテキストを食い、モデルも選びにくくなります。
  特定の作業でしか使わないツールは、モデルに直接割り当てるのではなく**スキルに紐づけて
  必要なときだけ載せる**ほうが有利です (「スキルの遅延ロード」を参照)。
- **チャット画面でツールを選びたい** — できません。使えるツールはモデルへの割り当てで決まります。
