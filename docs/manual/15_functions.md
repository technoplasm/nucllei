# ワークスペース: 拡張 (Functions)

この文書は、サーバー側で動く拡張コードを一覧・作成・編集する画面の説明です。画面上のタブ名は「拡張」です。

## 拡張とは

拡張は、**リクエストや応答の流れに割り込んで処理を足す Python のコード**です。ツールと違い、モデルが呼び出すものではなく、システムが決められたタイミングで自動的に実行します。

4 種別が流れのどこに割り込むかの図と、ツール・スキルとの対比は「ツール・スキル・拡張の違い」(`18_mechanisms.md`) にあります。

種別は 4 つあります。種別はコードの中のクラス名 (`Filter` / `Attachment` / `Action` / `Pipe`) で決まります。

| 種別       | 動くタイミング                                       | 用途の例                                             |
| ---------- | ---------------------------------------------------- | ---------------------------------------------------- |
| Filter     | モデルへ送る前 (`inlet`) と応答を受けた後 (`outlet`) | 入力の書き換え、パラメータの調整、ログ、応答の後処理 |
| Attachment | ファイルがアップロードされたとき                     | ファイルからテキストを抽出して本文にする             |
| Action     | 応答の下に出るボタンを人が押したとき                 | 応答に対する後付けの操作                             |
| Pipe       | モデルとして選ばれたとき                             | 独自のモデル・ルーティングを作る                     |

**Filter と Action は、どのモデルに適用するかを「ワークスペース > モデル」の編集画面で割り当てます。** 割り当てていないモデルでは動きません。

**Attachment は「ワークスペース > 設定 > ファイル」の「Attachment Function」で 1 つだけ選びます。** 選んだものがすべてのアップロードで動きます。

## どこにあるか

左サイドバー > ワークスペース > 「拡張」

## 誰が使えるか

**管理者のみ**です。管理者以外にはタブが表示されません。拡張には公開範囲の設定がありません (誰に効くかはモデルへの割り当てで決まります)。

## 一覧画面

上部に「拡張を作成」ボタンと検索ボックス (「Functionの検索」) があります。検索は名前と ID の部分一致です。

一覧は種別ごとの節に分かれ、`Attachment` / `Filter` / `Action` / `Pipe` の順に並びます (該当する拡張が 1 つも無い種別は表示されません)。いずれにも当てはまらないものは末尾に `Other` としてまとまります。これらの見出しは英語のまま表示されます。

カードには次が並びます。

| 位置             | 意味                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 名前 (太字)      | 表示名。カードのクリックで編集画面が開きます                                       |
| 2 行目           | 拡張 ID と説明                                                                     |
| 歯車のアイコン   | 「設定値」。その拡張が設定値を持たないときは押せず、「設定値はありません」と出ます |
| ごみ箱のアイコン | 「削除」。確認ダイアログが出ます                                                   |

### 設定値

歯車のアイコンから「設定値」ダイアログが開きます。拡張のコード側で宣言した設定項目をここで入力し、「保存」で反映します。

## 作成・編集画面

「拡張を作成」またはカードのクリックで開きます。

| 項目           | 意味                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 「名前」       | 表示名。必須です                                                                                                                 |
| 種別の選択     | **新規作成時だけ**、名前の右にドロップダウンが出ます。`Filter` / `Attachment` / `Action` / `Pipe` から選べ、既定は `Filter` です |
| 「ID」         | 内部で使う識別子。必須です。新規作成時は名前から自動生成されます                                                                 |
| 「説明」       | 一覧に出る短い説明。空でも構いません                                                                                             |
| 「拡張の内容」 | Python コード。エディタで編集します                                                                                              |

新規作成時の種別ドロップダウンは、**エディタに差し込む雛形を切り替えるためのもの**です。実際の種別は保存されたコードのクラス名で決まります。編集画面では種別はドロップダウンではなく、名前の右のバッジで表示されます。

「保存」を押すと、コードが自動で整形されてから保存されます。**整形できないコード (構文エラーなど) は保存されません。**

## ID を変更したときの注意

編集画面で「ID」を書き換えて保存しようとすると、「ID を変更しますか？」という確認が出ます。

**ID の変更は「古い ID の削除 + 新しい ID での作成」として行われます。** その結果、

- 他の項目からこの拡張への割り当てや参照は外れます (モデルへの割り当ても外れます)
- 設定値などの項目別設定はリセットされます

## つまずきやすいところ

- **拡張が動かない** — Filter / Action はモデルへの割り当てが必要です。Attachment は「ワークスペース > 設定 > ファイル」で選ばれている 1 つだけが動きます。
- **種別が思った通りにならない** — 種別はコード中のクラス名で決まります。雛形を `Action` で入れても、クラス名を `Filter` に書き換えれば Filter として扱われます。
- **保存しても反映されない** — 構文エラーがあると整形の段階で止まり、保存されません。
