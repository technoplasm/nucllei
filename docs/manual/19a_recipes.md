# 仕組み: レシピ

この文書は、利用者が残す手順「レシピ」の仕組みの説明です。レシピはチャットの中で、モデルに頼んで作る・使う・直すものです。専用の画面はありません。

## レシピとは

レシピは「いつもの集計のやり方」「この様式の書き方」のような、繰り返し使う手順を残したものです。チャットで一度やった作業を「この手順をレシピとして残して」と頼むと、モデルがレシピにします。次からは「いつもの集計で」と頼めば、モデルがそのレシピを読み込んで同じ手順で進めます。

レシピはサンドボックス ([12a サンドボックス](12a_sandbox.md)) の中に、1 つのフォルダとして置かれます。

| 置き場   | パス                                       | 見える人           | 書ける人                                                                              |
| -------- | ------------------------------------------ | ------------------ | ------------------------------------------------------------------------------------- |
| 個人     | `/workspace/recipes/<名前>/`               | 本人だけ           | 本人                                                                                  |
| グループ | `/ext/groups/<グループ名>/recipes/<名前>/` | グループのメンバー | 管理者が書き込みを許したメンバー (ほかのメンバーは読むだけ)。管理者はすべてのグループ |
| 全体     | `/ext/public/recipes/<名前>/`              | 全員               | 管理者                                                                                |

フォルダの中には、手順の本体の `RECIPE.md` と、手順で使う付属のファイル (SQL のひな形・スクリプトなど) が入ります。

レシピのフォルダは、ワークスペースの「サンドボックス」の画面 ([12a サンドボックス](12a_sandbox.md)) で、それぞれの置き場の `recipes/<名前>/` を開けば見られます。書ける置き場なら、そこで `RECIPE.md` や付属のファイルを直接編集することもできます。ただし、この画面での編集には次の「書く前の検査」がかかりません。書式が崩れると一覧で「壊れている」と出るので、そのときはモデルに直してもらってください。この画面で削除すると、個人の置き場ではゴミ箱 (`/workspace/trash/`) に移りますが、グループ・全体の置き場では完全に削除され、戻せません。モデルに「〇〇のレシピを消して」と頼んだときは、どの置き場でもその置き場のゴミ箱 (`trash/`) に移ります。

## 使えるかどうか

レシピは、そのモデルの「能力」で「レシピ」がオンのときに使えます ([11 モデル](11_models.md))。既定はオンです。サンドボックスのある配備でだけ働きます。「レシピ」を外したモデルでは、レシピを読み込む・作る・直すことはできません。モデルに頼んでも、管理者に「レシピ」をオンにしてもらうよう案内されます。

「ツール」で Sandbox を選んでいないモデルでも、レシピの読み込みと、そのとき先に読む資料 (付属のスクリプトの実行を含む) は動きます。ただし、レシピの手順の中でモデルが自分で付属のスクリプトを動かすには、Sandbox が要ります。

## 使えるレシピの一覧

「レシピ」がオンのモデルには、使えるレシピの一覧が最初から渡されています。モデルのシステムプロンプトに `{{USER_RECIPES}}` と書くとそこに一覧が入り、書かなければレシピを読み込むツールの説明に入ります ([13 スキル](13_skills.md) の変数の表)。モデルは一覧を見て、用件に合うレシピがあればそれを読み込みます。一覧に出るのは、個人のレシピと、所属しているグループのレシピと、全体のレシピです。管理者でも、所属していないグループのレシピは出ません。

一覧には、レシピのパスのすぐ後ろに「(壊れている: …)」「(警告: …)」の印が付くことがあります。印はシステムが付けるもので、説明 (description) に同じ形を書いても印にはなりません。

- **「壊れている」** — レシピの先頭の設定 (題・説明・作った人・更新日・先に読む資料) の書き方に誤りがあり、そのままでは読み込めません。知らない項目名 (綴り違いなど) があるときもこうなります。理由も一緒に出ます。直せるのは、自分が書ける置き場のレシピ (自分の個人のレシピと、書き込みを許されているグループのレシピ) で、モデルに「このレシピを直して」と頼めば直せます。全体のレシピと、読むだけのグループのレシピでは、モデルは壊れていることを伝えるだけです。全体のレシピは管理者が、グループのレシピは管理者かそのグループで書き込みを許されたメンバーが直します。
- **「警告」** — レシピは読み込めますが、そのままでは通らないところがあります。次の 2 種類です。
  - 先に読む資料のうち、そのまま読めないもの — 参照しているもの (ファイル・別のレシピ) が今は無いか、所属していないグループのものであなたには見えないか、その置き場のレシピでは許されない資料 (下の「先に読む資料」) です。読めない資料だけを飛ばし、モデルにはその理由が伝わります。参照先を元に戻せば、警告は消えます。参照先がもう要らないなら、モデルに「先に読む資料から外して」と頼んでください。
  - 使える人が限られる関数 (例: 電子カルテの検索) の名前がレシピに書かれていて、あなたがその関数を使えるグループに所属していないもの — レシピ全体への警告です。読み込むと本文の前に警告が置かれ、モデルはその関数を使う手順を飛ばして、使えないことを伝えます。先に読む資料から外しても消えません。その関数を使うには、関数を使えるグループに入れてもらうよう管理者に頼みます。その関数が要らない手順なら、レシピからその関数の名前を消すよう、レシピを直せる人に頼みます。

## 頼めること

- **作る** — 「この手順をレシピとして残して」。置き場を言わなければ個人に置かれます。グループや全体に置くときは「EMR グループに置いて」のように言います。
- **使う** — 「いつもの〇〇で」「〇〇のレシピで」。モデルがレシピを読み込み、その手順で進めます。
- **直す** — 「〇〇のレシピの 3 番を直して」。一部だけを書き換えます。題 (title) や説明 (description) も直せます。同じチャットで一度読み込んだレシピでも、直した後にもう一度使うと、新しい版が最初から読み込まれます。
- **書き直す** — 「〇〇のレシピを丸ごと書き直して」。前の版は、その置き場のゴミ箱 (`trash/`) に `<名前>.RECIPE.md` として移ります。
- **別の置き場へ写す** — 「個人の〇〇のレシピをグループに写して」。付属のファイルも一緒に写ります。写し元はそのまま残ります。
- **消す** — 「〇〇のレシピを消して」。フォルダごと、その置き場のゴミ箱に移ります。ゴミ箱のものは一定期間 (既定は 30 日) で自動で消え、それまでは戻せます。

グループや全体のレシピは、その置き場に書ける人なら誰でも直せます。グループのレシピを直せるのは、管理者が書き込みを許したメンバーと管理者です ([16 ユーザー](16_users.md) のグループの「書き込み」)。ほかのメンバーにとってグループの置き場は読むだけで、サンドボックスの場所の切り替えに鍵のアイコンが付きます。全体のレシピを直せるのは管理者だけです。直せない人がモデルに直すよう頼むと、モデルは直せないことを伝えます。一般の利用者は、全体のレシピなら管理者に、グループのレシピならそのグループで書き込みを許された人か管理者に頼んでください。直すと「誰のレシピを直したか」が返答に出ます。作った人 (author) は直しても変わりません。

## 書く前の検査

モデルがレシピを作る・直すときは、書く前にフォルダ全体 (付属のファイルを含む) が検査されます。次のものが見つかると何も書かれず、モデルが直してからやり直します。

- 患者の番号・氏名らしきもの。レシピには患者のデータを置きません。患者番号は `{患者番号}` のような記号に置き換えます
- 手順の本体の書式の崩れ
- グループや全体に置けないもの (その置き場の全員が使えるとは限らない関数、他の人には見えない個人の場所のパス)

参照しているファイルやレシピがまだ無いとき、先に読む資料が置き場の決まり (次の節) に反するときは、止まらずに書けます。そのときは返答に警告が出ます。

具体的な日付は「注意」として示されるだけで、止まりません。患者の日付なら記号にし、ガイドラインの改定日などならそのまま残します。どちらかはモデルが判断します。

## 先に読む資料

レシピには、読み込んだときに本文より先に読む資料を書いておけます (例: 決まったファイルを読む、別のレシピも一緒に読み込む、付属のスクリプトを動かしてその出力を見る)。レシピを読み込むと、資料を書いた順に並べ、レシピの本文を最後に置いて、1 つの結果としてモデルに渡します。資料を先に、手順を最後に読ませるためです。各資料にはそれぞれ見出しが付きます。同じ資料を読むのはチャットにつき 1 回です。

スキルは資料に書けません。スキルを使うかどうかはモデルが判断します。

自動で動かせるスクリプトは、そのレシピのフォルダに入っている付属のファイルだけです。任意のコマンドは書けません。スクリプトが失敗しても、その資料のところにエラーが 1 行出るだけで、ほかの資料と本文は読み込まれます。資料が長すぎるときは途中で切られ、どこで切ったかが示されます。

チャットでは「Toolの使用 **load_recipe**」のブロックを開くと、読み込んだ資料が書いた順に 1 行ずつ並びます。行には資料の種類 (`read` / `shell` / `python` / `recipe`)、対象、状態 (「済」「読み込み済み」「警告」「ERROR」) が出て、警告とエラーは理由も表示されます。行を押すとその資料の中身が開きます (一緒に読み込んだレシピは、その下に同じ形で入れ子になります)。最後にレシピの本文が出ます。警告やエラーがあるときは、ブロックの見出しに三角の印と件数が付きます。

グループや全体のレシピは他の人も読み込むので、先に読む資料として参照できるものが限られます。参照は「狭い置き場から広い置き場へ」の向きだけです。

| レシピの置き場 | 別のレシピ               | ファイル                                                                   | スクリプト |
| -------------- | ------------------------ | -------------------------------------------------------------------------- | ---------- |
| 個人           | 個人・所属グループ・全体 | 見えるものならどこでも                                                     | 動かせる   |
| グループ       | そのグループと全体       | そのグループ・全体の置き場、そのレシピのフォルダ、全員が読める資料の置き場 | 動かせない |
| 全体           | 全体                     | 全体の置き場、そのレシピのフォルダ、全員が読める資料の置き場               | 動かせない |

グループや全体のレシピから、読み込んだ人の個人の場所 (`/workspace`) のファイルは読めません。自分の記録や書き出したデータが、他の人のレシピに読まれないようにするためです。グループや全体のレシピと一緒にスクリプトを動かしたいときは、自分の個人のレシピにスクリプトを置き、そこからグループや全体のレシピを読み込みます。決まりに反する資料は、読み込んでも読まれず、警告になります。

## つまずきやすいところ

- **「壊れている」と出る** — 理由のとおりに直します。書ける置き場のレシピなら、モデルに「直して」と頼めば直せます。丸ごと書き直してもかまいません。書けない置き場のレシピは、直せる人に頼んでください (上の「使えるレシピの一覧」の「壊れている」)。
- **「警告」と出る** — 先に読む資料が消えたか、所属していないグループのものか、置き場の決まりに反する資料です。消えたものは元に戻すか、先に読む資料から外します。所属していないグループのものは、そのグループの人に頼んでください。決まりに反する資料は、先に読む資料から外すか、個人のレシピへ移します。使えない関数の警告 (レシピ全体への警告) は先に読む資料とは別で、直し方は上の「使えるレシピの一覧」の「警告」のとおりです。
- **レシピを直してと頼んだら、直せないと言われた** — その置き場に書けません。全体のレシピは管理者に、グループのレシピはそのグループで書き込みを許された人か管理者に頼んでください。
- **レシピを書こうとすると止まる** — 書く前の検査で何かが見つかっています。理由はモデルの返答に出ます。患者のデータらしきものなら、記号に置き換えてもらってください。
- **グループのレシピが見えない** — そのグループに所属していません。所属は管理者が「ワークスペース > ユーザー」の「グループ」で設定します。
- **サンドボックスの画面で `RECIPE.md` を直接編集したら「壊れている」と出た** — 画面での編集には書く前の検査がかからないためです (上の「レシピとは」)。モデルに直してもらってください。
- **「sandbox が古い」と出る** — サーバー側の更新が必要です。管理者に伝えてください。
