# ワークスペース: モデル

この文書は、チャット画面のモデル一覧に出てくる「モデル」を作成・編集する画面の説明です。

## モデルとは

nucllei でいうモデルは、**推論エンジンから取り込んだ素のモデルに、名前・アイコン・システムプロンプト・使えるツールやスキル・公開範囲をひとまとめにしたもの**です。チャット画面のモデル一覧に出てくるのは、この画面で作ったモデルだけです。

素のモデル (接続先から取り込まれたもの) をそのままチャットで使うことはできません。素のモデルは「ワークスペース > 設定 > モデル」で一覧を確認でき、この画面で「ベースモデル (From)」として選ぶことで初めてチャットから使えるようになります。

## どこにあるか

左サイドバー > ワークスペース > 「モデル」

## 誰が使えるか

**管理者のみ**です。管理者以外にはタブが表示されません。

## 一覧画面

上部に「モデルを作成」ボタンと検索ボックス (「モデル検索」)、その右に並べ替え用のボタンがあります。検索は名前と ID の部分一致です。

一覧はカード表示で、チャットのモデル一覧と同じ並び順になります。並び順に含まれないモデル (無効にしているものなど) は末尾に名前順で並びます。

カードの構成は次のとおりです。

| 位置             | 意味                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 左のアイコン     | モデルの画像。無効なモデルは薄く表示されます                       |
| 名前 (太字)      | モデルの表示名。カードのどこをクリックしても編集画面が開きます     |
| 2 行目           | 説明。説明が空のときはモデル ID                                    |
| コピーのアイコン | 「クローン」。この設定を引き継いだ新しいモデルの作成画面を開きます |
| ゴミ箱のアイコン | 「削除」。確認ダイアログが出ます                                   |
| 右端のスイッチ   | 「有効」/「無効」。無効にするとチャットのモデル一覧から消えます    |

「クローン」で開く作成画面では、ID の末尾に `-clone`、名前の末尾に `(Clone)` が付いた状態から始まります。

### 表示順と既定モデルを変える

検索ボックスの右にある上下矢印のボタン (ツールチップは「表示順と既定モデル」) を押すと、「モデルを設定」ダイアログが開きます。

- **「モデルを並べ替え」** — 各行の左のつまみをドラッグして順番を入れ替えます。「モデルを並べ替え」の文字自体を押すと名前順に並べ替わり、押すたびに昇順と降順が入れ替わります。
- **「デフォルトモデル」** — 新しいチャットで最初に選ばれるモデルです。「なし(表示順の先頭)」を選ぶと、表示順の一番上のモデルが使われます。利用者が自分でモデルを固定している場合は、そちらが優先されます。
- **「全モデルをリセット」** — 押すと確認ダイアログが出たうえで、カスタムモデルを含むすべてのモデルが削除されます。元に戻せません。
- 変更は「保存」を押すまで反映されません。

## モデルの作成・編集画面

一覧の「モデルを作成」またはカードのクリックで開きます。左側に「一般」「プロンプト」「高度なパラメータ」の 3 つの縦タブがあり、右側にその内容が出ます。最後に「保存して作成」または「保存して更新」を押すと確定します。

**タブを切り替えると、開いた直後の状態に戻ります。** 別のタブでの編集を保存したいときは、タブを移動する前に保存してください (名前と ID は例外で、タブを移動しても保持されます)。

### 「一般」タブ

| 項目                        | 意味                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| 「名前」                    | チャットのモデル一覧に出る表示名。必須です                                                 |
| 「ID」                      | 内部で使う識別子。必須です。新規作成時は名前から自動生成されます                           |
| 「ベースモデル (From)」     | 実際に推論を行う素のモデル。必須です                                                       |
| モデル画像                  | 右上の四角い画像をクリックすると画像ファイルを選べます。「画像をリセット」で既定に戻ります |
| 「説明」                    | 一覧の 2 行目に出る短い説明                                                                |
| 「公開範囲」                | 後述                                                                                       |
| 「能力」(Capabilities)      | 後述                                                                                       |
| 「スキル」                  | このモデルに割り当てるスキルの一覧                                                         |
| 「サブエージェント preset」 | このモデルが作業を委任できるモデルの一覧                                                   |
| 「ツール」                  | このモデルが呼び出せるツールの一覧                                                         |
| 「拡張」                    | このモデルに適用する拡張 (「フィルター」/「アクション」) の一覧                            |

#### 「公開範囲」

「公開」と「非公開」を切り替えるボタンです。

- **「公開」** — 「全ユーザーがアクセス可能」。全員のモデル一覧に出ます。
- **「非公開」** — 「選択したユーザー・グループのみアクセス可能」。下に出る入力欄 (「グループ・ユーザーを追加」) にグループ名や利用者名を入力して候補から選ぶと、対象が札 (チップ) として追加されます。札の ✕ を押すと外れます。空欄のまま Backspace を押すと末尾の札が外れます。

#### 「能力」(Capabilities)

チェックボックスが並びます。各項目にマウスを乗せると意味の説明が出ます。

| 項目                               | 意味                                                                                                                                                                                                                       | 既定 |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 「スキル」                         | スキル一覧をモデルに提示し、`/コマンド` での起動も有効にします。外すとこのモデルではスキルが発火しません (割り当て自体は残ります)                                                                                          | オン |
| 「レシピ」                         | レシピの読み込み・保存・修正をモデルができるようにし、利用者に見えるレシピの一覧もモデルに渡します ([19a レシピ](19a_recipes.md))。サンドボックスのある配備でだけ働きます。「ツール」で Sandbox を選んでいなくても使えます | オン |
| 「画像認識」(vision)               | モデルが画像入力を受け付けます                                                                                                                                                                                             | オフ |
| 「使用量」(usage)                  | 実測のトークン消費を取得します。これを未知のパラメータとして拒否する OpenAI 互換 API に繋ぐときだけ外します                                                                                                                | オン |
| 「思考の保持」(preserve_reasoning) | モデルがツールを呼んだ後の続きのリクエストに、同じターンのモデルの思考を載せ直します。ツールを呼ぶたびに直前の思考を失わずに済みます。思考を受け付けない・読み違える OpenAI 互換 API に繋ぐときだけ外します                | オン |

#### 「スキル」の割り当て

チェックを入れたスキルがこのモデルで使えるようになります。行には `/スキル ID — スキル名` の形で表示されます。説明が空のスキルには「(説明なし)」と黄色で注記が付き、モデルには公開されません。

「能力」の「スキル」を外している場合は、この欄の上に「スキル機能が無効のため、このモデルでは発火しません(紐づけ設定は保持されます)」と表示されます。

#### 「サブエージェント preset」の割り当て

このモデルが作業を委任できる相手を選びます。一覧には作成済みのモデルが表示名順で並びます。チャットのモデル一覧から外している (無効にしている) モデルにも「一覧非表示」の札が付いて表示され、委任先としては選べます。裏方専用のモデルを用意したいときに使えます。

委任の機能そのものは、次のどちらかのときだけ有効になります。

- 下の「ツール」で組み込みツール「Subagent」(`builtin_subagent`) を割り当てている
- 「Subagent」をツールに持つスキル (スキルの「ツール」に `builtin_subagent` を入れたもの) を「スキル」で割り当てていて、「能力」の「スキル」がオンになっている。この場合、委任の機能はそのスキルが読み込まれてから使えるようになります

この欄の上には「ツールに Subagent(builtin_subagent)を割り当てるか、それを tool に持つスキルを割り当てたときだけ有効になります。スキル経由の場合、使える人はそのスキルの公開範囲で決まります」と表示され、どちらにも当てはまらない間は黄色で表示されます。ここで選んだ相手の割り当ては、ツールやスキルを割り当てていなくても保存されます。

委任の機能を使える利用者を絞りたいときは、割り当て方に合わせて公開範囲を設定します。

- ツールとして割り当てたとき — 「ワークスペース > ツール」で「Subagent」の公開範囲を設定します (他のツールと同じです)。
- スキル経由のとき — そのスキルの公開範囲で決まります (「Subagent」ツールの公開範囲は使われません)。管理者も公開範囲に入っていなければ使えないので、管理者にも使わせるときは公開範囲に入れてください。

公開範囲に入っていない利用者には、委任先を選んであっても提示されません。

#### 「ツール」の割り当て

「組み込み」と「カスタム」の 2 つの節に分かれます (両方ある場合のみ小見出しが出ます)。行にはツール名と、そのツールが公開する関数名が並びます。関数名にマウスを乗せると、その関数の説明が出ます。

**チャット画面でツールを選ぶ仕組みはありません。** ここで割り当てたツールだけがそのモデルで使えます。

#### 「拡張」の割り当て

「フィルター」「アクション」の種別ごとに分かれてチェックボックスが並びます (「ワークスペース > 拡張」の一覧の見出しと同じ呼び名です)。該当する種別の拡張が 1 つも無い場合、その小見出しは表示されません。

### 「プロンプト」タブ

- **「プロンプトの提案」** — 新しいチャットの画面に出る定型の問いかけです。右の「+」で行を追加し、上段に「タイトル(例: あいさつ)」、下段に「プロンプト(例: あなたは誰？簡単なデモを見せて。)」を入れます。**両方を埋めないと保存できません**。行の ✕ で削除します。
- **「システムプロンプト」** — このモデルに常に与える指示文です。Markdown 用のエディタで編集します。`{{CURRENT_DATE}}` や `{{USER_NAME}}` などの変数を書くと、リクエストのたびに値が差し込まれます (一覧は [13 スキル](13_skills.md))。`{{BASE_MODEL_ID}}` には「ベースモデル」の ID (実際に推論するモデル) が入るので、ベースモデルを差し替えてもプロンプトを書き直さずに済みます。
- **「編集」「プレビュー」** — 「システムプロンプト」の右上で切り替えます。「プレビュー」では、**編集中 (保存前) のシステムプロンプトで新しいチャットを始めたとき、モデルに何が渡るか**を、**自分として**展開して見せます。上から順に、モデルに渡るツール (名前と説明。各行を開くと説明と引数) → システムプロンプトです。何も実行しません。
  - 色分け: **「利用者ごとに変わる」**(黄 — `{{USER_NAME}}`・`{{SKILLS}}` など、ツールの説明に入るスキルやレシピの一覧も)、**「日時で変わる」**(青 — `{{CURRENT_DATE}}` など)、**「モデルの値」**(点線の下線 — `{{BASE_MODEL_ID}}`)、**「ここでは展開しない (空)」**(赤の取り消し線 — その場所では空になる変数。システムプロンプトに書いた `{{USER_MEMORY_INDEX}}`・`{{USER_RECIPES}}` など。上に赤字で「会話の前置きに書いてください」と出ます)。自分には空になる変数は、変数名が点線の枠で出ます。それ以外は、このモデルを使う全員で同じ文です。推論サーバーの再利用 (キャッシュ) は先頭から同じ部分にしか効かないので、利用者ごとに変わる部分はなるべく後ろに置きます。
  - 各部分に文字数とトークン数の概算 (ASCII は 4 文字 ≈ 1、それ以外は 1 文字 ≈ 1) が出ます。
  - ツール・スキル・能力は**保存済みの設定**で組みます (タブを切り替えると「一般」の未保存の変更は戻るため)。他の利用者として見ることはできません (その人の個人のレシピ名が見えてしまうため)。チャットの履歴・添付・`/コマンド` で読み込むスキルのツール、拡張 (フィルター) による変更は入りません。どのツールが入るかは、利用者の権限によっても変わります。
  - 「再読み込み」で取り直します。「編集」に戻っても書きかけはそのまま残ります。
- **「会話の前置き」** — 「システムプロンプト」のすぐ下にある 2 つ目のエディタです。会話の**最初の発言の先頭**に一度だけ入る文で、利用者の記憶の目次 (`{{USER_MEMORY_INDEX}}`) と見えるレシピの一覧 (`{{USER_RECIPES}}`) はここに書きます (この 2 つが展開されるのは会話の前置きだけで、システムプロンプトやスキルの本文に書いても空になります)。見出しなど前後の文も一緒に書きます。空にすると前置きは入りません。
  - 前置きは会話を始めたときの内容で**固定**され、そのチャットの間は毎回同じものが送られます (推論サーバーの再利用が会話全体に効きます)。会話の途中で記憶やレシピが変わると、その次の発言の先頭に、変わった分だけが「更新」として入ります。
  - 日付・時刻や利用者の名前・グループなどの変数は、会話の前置きでは空になります (固定されると古くなるため)。これらはシステムプロンプトに書きます。
  - 前置きもチャットの添付の本文も、チャット画面には出ません (画面に出るのは利用者が書いた文だけです)。添付の本文は、そのファイルを付けた発言の先頭 (前置きの後) に入ります。
  - サブエージェントとして動くときは、前置きは使われません。
- **「編集」「プレビュー」(会話の前置き)** — 「会話の前置き」の右上で切り替えます。「プレビュー」では、編集中の前置きを**自分として**展開し、記憶の目次とレシピの一覧が**どう展開されるか**と**どこに入るか**を見せます。上から、ツールとシステムプロンプトの帯 → 枠 (`<conversation-context>`) に入った前置き → 添付があればその本文が入る位置 → 「ここに利用者の最初の発言」です。色分けはシステムプロンプトのプレビューと同じで、会話の前置きでは展開しない変数 (日付など) は赤の取り消し線で出ます。

### 「高度なパラメータ」タブ

推論時のパラメータを項目ごとに指定します。ラベルはサーバーに渡すキー名そのものです。「動作」「サンプリング」「Mirostat」「Ollama」「カスタム」の節に分かれています。

- 各行は既定では「デフォルト」と表示され、その項目を指定していない状態です。「デフォルト」を押すと値が現れ、スライダーや入力欄で調整できます。
- 値を指定している行には ✕ が出ます。✕ を押すと「デフォルト」に戻ります。
- 「カスタム」節では、上の一覧に無い任意のキーと値を追加できます。値は JSON として解釈され、JSON として解釈できない入力は文字列として扱われます (`thinking` → 文字列、`true` → 真偽値、`{"a":1}` → オブジェクト)。

## ID を変更したときの注意

編集画面で「ID」を書き換えて保存しようとすると、「ID を変更しますか？」という確認が出ます。

**ID の変更は「古い ID の削除 + 新しい ID での作成」として行われます。** その結果、他の項目からこのモデルへの割り当てや参照は外れます。既存のチャットからの参照も切れます。

## つまずきやすいところ

- **チャットのモデル一覧に出てこない** — モデルが「無効」になっていないか、「公開範囲」が「非公開」で自分が対象に入っていないかを確認してください。
- **保存したはずの設定が消えている** — 保存前にタブを切り替えると、そのタブ以外の編集は開いた直後の状態に戻ります。
- **同じ ID のモデルは作れません。** 作成時に既存の ID を指定すると、そのモデルは既に存在するというエラーが出ます。
