# llens ドキュメント同期(セッションの区切り処理)

/catchup が「読む側」、これは「書く側」。以下を順に行い、最後に同期内容を 1 つのレポートにまとめる。
書く前に必ず現状を読む(コミット済み内容と重複して書かない。真実源は git log と実装)。

## 0. 同期対象の洗い出し

```bash
git log --oneline --since="12 hours ago" master   # 今日のコミット(コミットメッセージの refs #N が対象 issue)
git status --short                                 # 未コミットがあれば先に始末(コミット or 破棄の判断を仰ぐ)
```

対象 issue = 今日のコミットの `refs #N` の和集合。設計判断があったのにコミットに現れないもの
(撤回・却下・保留)も忘れず拾う — 会話の中の決定は消えやすいので必ずどこかに書く。

## 1. 設計メモ(`_memos/`)の追従

- 対象 issue に対応する設計メモ(例: #35 → `skill-design.md`)を読み、実装との乖離を潰す:
  - 完了した項目のチェックボックス化([ ] → [x] + 出荷コミット hash)
  - 撤回・改訂した設計は**上書きでなく「改訂(日付)+ 理由」**で書く(なぜ変えたかが後で効く)
  - 「検討中」「TODO」で実装済みになったものを昇格
- `dev-environment.md`: セッションで得た dev の罠・手順・fixture を反映
  (新しい環境で再現するのに必要な知識か?が採録基準)。

## 2. 作業 issue へのコメント記録

対象 issue ごとに `gh issue comment` で進捗を記録する。書式は既存コメントに合わせる:

- 出荷したもの(コミット hash 付き)/ 設計の改訂(理由込み)/ 検証結果(テスト数・実機 PASS)
- 残タスク(なぜ残るか・何を待つか)
- 1 セッション複数コメントより、区切りでのロールアップ 1 つを好む

## 3. tracking issue #16 の同期

```bash
gh issue view 16 -R technoplasm/nucllei --json body --jq .body > /tmp/issue16.md
```

- 完了したトラック項目を [x] + 一行サマリ + コミット/日付に更新(python で該当ブロックだけ置換し、
  `gh issue edit 16 --body-file`。**本文全体を書き直さない**)
- 別トラックへ移動した残タスク(例: async 化は C へ)は移動先に明記
- closed にすべき issue(実装が終わっているのに open)があれば報告し、ユーザーの確認を得て close

## 4. タスクリスト・memory の掃除

- TaskList の完了済みを確認し、次セッションに持ち越すものだけ残す(不足があれば TaskCreate)
- このリポジトリの一次情報は `_memos/` と issue — Claude の個人 memory には
  リポジトリに書けない事情(ユーザーの好み・環境固有)だけを書く

## 5. コミットとレポート

- メモ・skill の変更は `docs:` でコミット(`refs #N` を忘れない)
- 最後にレポート: 更新したメモ / 記録した issue コメント(URL)/ #16 の変更点 /
  持ち越しタスク一覧。**次の一手**を /catchup と同じ基準(#16 実行順)で 1 つ提案する
